# Private Windows dependency write trees

Explicit medium-integrity labels can prevent AppContainer writes despite DACL grants. General execution separately validates ordinary existing declared targets without lowering their labels. Prepare only freshly copied private dependency write targets with low mandatory labels and inheritable no-write-up labels on directories. Validate the complete tree before any label change, then validate every declared write object again before launch. Reject reparse points and file hard links, and preserve owner and DACL permissions. Windows can update inheritance bookkeeping inside the private copy when propagating labels. Never lower the integrity of developer sources or shared store trees. Concurrent host mutation between validation and native updates remains outside the trusted-host boundary.

This extends the existing private BuildStage and AppContainer grant machinery. This private-copy path does not enable networking, weaken ManagedTree, or establish authenticated dependency support without native CLI acceptance and toolchain identity. Native owner-only lifecycle keys use a protected DACL and held non-inheritable handles, matching the Unix key contract.
