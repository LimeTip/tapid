# Tapid 0.0.7 release notes

Tapid 0.0.7 is the first development release intended to exercise a complete verified npm installation flow against a real JavaScript/TypeScript application.

## Installation

- Resolves supported transitive npm dependency ranges deterministically.
- Selects compatible optional packages using bounded `os`, `cpu`, and `libc` metadata.
- Preserves exact multi-version identities and Node-compatible shadowing and hoisting.
- Materializes package executables and platform-native packages without running dependency lifecycle scripts.
- Preserves normalized executable archive modes and binds executable behavior into platform-independent verified tree digests.
- Uses a platform cache outside the consumer project as the default verified store.

## Security and recovery

- Rejects noncanonical artifact URL representations after parsing and before transport.
- Uses bounded metadata/artifact transport, exact-origin redirects, canonical SHA-512 integrity, and verified tree digests.
- Recovers interrupted installation stages, activation backups, and stale replay snapshots while preserving unowned paths.
- Uses safe cross-platform file identity and advisory-lock abstractions where practical; the remaining macOS `clonefile` FFI is narrowly scoped and independently verified.

## Lockfiles and migration

- Schema 6 records exact sorted roots, platform-aware package identities, and whether registry metadata declared each artifact integrity value.
- Controlled schema 4 replay is limited to canonical or empty contexts and canonically padded integrity.
- Schema 3 and earlier must be regenerated online.
- Existing schema 5 development locks must be regenerated online because schema 6 makes registry-integrity provenance mandatory and tree identity includes normalized executable behavior.
- Legacy project-local `.tapid-store` directories are not moved or deleted automatically.
- Before migration, replay a legacy project-local store explicitly with `tapid install --offline --store-dir ./.tapid-store`; after a successful online install has populated the external default store, remove the legacy directory deliberately.

## Current limits

Tapid still implements an explicit npm-compatible subset. Full npm semver, tags, aliases, peers, workspaces, private registry authentication, add/remove/update/prune, complete optional semantics, and lifecycle-script approval are not yet complete. JSR installation remains fail-closed unless metadata supplies an HTTPS npm artifact and valid SHA-512 integrity.
