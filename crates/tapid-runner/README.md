Policy-aware package execution foundations for Tapid. Existing approval APIs bind an exact artifact digest to the SHA-256 hash of a normalized script.

`RunConfig::parse_toml` accepts checked-in `[run.defaults]` and `[run.scripts.<name>]` profiles. Profiles declare project-relative read/write grants, network access, environment-variable names, subprocess access, and optional resource limits. `/` is the sole portable path separator; backslashes are rejected on every host. Configuration is strict, denies unknown fields, and cannot disable required sandboxing.

The platform-neutral execution API validates requests and reports stable errors, termination states, and per-dimension containment evidence. Backend identities use checked construction: name, version, and optional deprecation text must be non-empty, free of control characters (including NUL), and no longer than `MAX_BACKEND_IDENTITY_BYTES`. Support and post-execution receipts distinguish restrictions requested by policy, capabilities declared by the backend, capabilities observed by runtime probes, and restrictions actually enforced for the execution. Each state reports filesystem read, filesystem write, network, environment sanitization, subprocess restriction, descendant lifecycle, timeout, output, process-count, and memory dimensions independently. Receipt fields and construction remain private, so external callers cannot manufacture enforcement claims.

`ExecutionRequest` carries only explicit environment values whose names are both valid and allowlisted by the selected policy. Published limits bound the program, argument count, each argument, cumulative argv payload, project root, each environment value, and the cumulative child environment block. Lengths are measured in bytes on Unix and UTF-16 code units on Windows. Embedded NUL and values that the target platform cannot represent are rejected before support probing; Unix otherwise preserves non-UTF-8 program, argument, project-root, and environment bytes. On Windows, argv validation uses a conservative upper bound rather than exact serialization: it counts the quoted program, argument separators, surrounding argument quotes, the mandatory terminating NUL, and worst-case doubling for quote/backslash escaping. Backends must start from an empty child environment rather than inherit ambient variables.

The sandboxed `execute` path rejects `SandboxMode::Disabled` and validates containment evidence before its private backend seam can add runtime paths or spawn. Existing project grants are canonicalized and retain typed `ExactFile` or `DirectorySubtree` semantics. A missing read target is rejected. A missing write target is declared as a directory subtree; the adapter must securely materialize it, re-resolve it, and bind it before native sandbox installation, or return unsupported containment. Explicit backend runtime additions must be absolute, existing, canonical, and retain their file/directory kind.

Receipts expose each effective grant's path, access, declared kind, source, and binding evidence. `NativeObject` means the adapter holds and revalidates a native object handle/identity for setup; pathname equality alone never makes that claim. `CanonicalPath` means the adapter freshly re-resolved the path immediately before setup. Canonical-path enforcement has a residual trusted-host assumption: a privileged or concurrently mutating host must not replace path components between revalidation and native sandbox installation. The generic layer binds the receipt's paths, access, kinds, sources, binding modes, enforcement dimensions, and configured limits to the exact private preflight and rejects mismatches. Outcome accounting checked-adds captured stdout and stderr byte lengths and requires their combined size to be no greater than the exact preflight `max_output_bytes`, when configured. `TimedOut`, `OutputLimitExceeded`, `ProcessLimitExceeded`, and `MemoryLimitExceeded` are accepted only when that exact preflight configured the corresponding limit.

No platform adapter is implemented in this crate yet, so `execute` fails closed before spawning a child and cannot produce an enforcement receipt. `SandboxMode::Disabled` exists only for a future distinct unsandboxed CLI outcome that must not contain an enforcement receipt; this crate does not implement that escape.
